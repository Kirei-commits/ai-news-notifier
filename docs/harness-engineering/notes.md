# 実装ノート

実装して初めて分かったこと、判断の理由の記録。コードだけでは再現できない部分を残す。

## Phase 1 — ループ

**ツール結果は 1 つの user メッセージにまとめる。**
分割して送ると「並列で呼んでも結果は別々に返ってくる」とモデルが学習してしまい、
以降のターンで並列ツール呼び出しをしなくなる。ターン数が倍増する。
`src/harness/loop.test.ts` の「並列ツール呼び出しの結果を 1 つの user メッセージにまとめる」で固定した。

**例外はループの外に出さない。**
未知のツール名・スキーマ違反・ツール内例外の 3 つは、どれもモデルに `isError` 付きの
結果として返す。落とすのは簡単だが、モデルは大半のケースで自力で直せる。
実際 eval の「不正な引数から自己修復する」は 3 ターンで復帰している。

**呼び出し回数のカウントは並列実行の前に確定させる。**
`Promise.all` の中でカウントすると、同一ターンに同じツールが 2 回来たとき両方が
`priorCalls = 0` を見てしまい、上限が効かない。

## Phase 2 — ツール

**エラーメッセージはプロンプトである。**
`invalid input` だけ返すとモデルは直せない。「何が」「どうあるべきか」「スキーマ全文」
「もう一度呼べ」の 4 点を書くと次のターンでほぼ確実に直る。`formatValidationError` がそれ。

**モデルの型はぶれる。** 数値を `"10"`、真偽値を `"true"` で返してくることがある。
スキーマ側で吸収した。逆に未知のキーは弾く — 黙って捨てるとツール設計のミスに気づけない。

**ツール出力のサイズ制御がコンテキスト管理の本体。**
`maxToolResultChars` による切り詰めはループ側の最終防衛線で、本来は各ツールが
最初から小さく返すべき（`fetch_feed` の `limit` はそのため）。

## Phase 0 — プロバイダ抽象

**内部表現には「理解できないものを持ち回る箱」が要る。**
Anthropic の thinking ブロックは署名付きで、次のリクエストに無改変で戻す必要がある。
内部表現を自分が解釈できるブロックだけに絞ると、これを落として 400 になる。
`OpaqueBlock` を最初から用意した。

**プロバイダ差は毎回同じ 4 箇所に出る。**
role 名 / ツール呼び出し ID の有無 / JSON Schema の方言 / 停止理由の語彙。
Gemini は呼び出し ID を返さないので、ハーネス側で採番し、`functionResponse` に
必要な関数名は会話履歴を走査して復元している。

## Phase 3 — コンテキスト

**tool_result のブロックを消してはいけない。** 中身だけを縮める。
ブロックごと落とすと `tool_use` と対応が取れず API が 400 を返す。
削減対象は「古いツール結果」でほぼ尽きる。

**圧縮結果は履歴に焼き込む。** 毎ターン元履歴から計算し直すと、同じ処理を繰り返すうえ、
プロンプトキャッシュの前方一致が毎回壊れてコストが跳ねる。

## Phase 4 — 権限

**判定はスキーマ検証の後に置く。** モデルの説明文ではなく、実際にツールへ渡る引数で判断する。

**ask は無人実行では deny に落とす。** GitHub Actions で確認待ちに入ると永久に固まる。
「止まる」より「やらない」の方が安全側。

**deny もモデルに返す。** 理由が分かれば、別の手段に切り替えるか制約を報告して終われる。
`Do not retry this call` を添えないと同じ呼び出しを繰り返してターンを浪費する。

## Phase 5 — 観測性

**トレースは 1 イベントずつ即時追記する。** バッファすると、一番トレースが欲しい
「クラッシュした時」に何も残らない。

**リプレイの価値は再生そのものではなく差分検出にある。**
`strict` モードで記録時とリクエスト形状を比べることで、ハーネスを触った結果
「モデルに渡るものが変わった」ことが API を呼ばずに分かる。

## Phase 6 — 評価

**固定すべきはモデルだけではなく環境。**
`evals/fixtures/fakeNews.ts` で RSS の中身・既読状態・投稿先をすべて偽物にした。
実 RSS で評価すると、スコアの変化が改善なのかその日のニュースの違いなのか判別できない。

**評価対象は最終出力よりも途中の挙動。**
「何を呼んだか」「何回呼んだか」「何ターンかかったか」「いくらかかったか」が
ハーネスの品質そのもの。アサーションはトレースから組み立てている。

**評価が空振りしていないかを確認する。**
`fetch_feed` から `<untrusted-data>` の囲みを外したら該当ケースが落ちることを確認済み。
落ちないアサーションは無いのと同じ。
